# 单例模式（Singleton）

> **一句话**：保证一个类**全局只有一个实例**，并且提供一个访问它的入口。

## 生活中的类比 🍚

想象你家里的电饭煲。全家人用一个电饭煲就够了对吧？你不需要每做一顿饭就买一个新的电饭煲。而且大家用的时候，用的是**同一个**电饭煲——洗米、煮饭、盛饭，都对着它来。

单例模式就是这个「全家人共用的电饭煲」：不管谁、在什么时间点来找它，拿到的都是同一个。

## 它解决什么问题？

在程序里，有些对象天生就应该是「一份」：

- **配置对象**：整个进程读的是同一份配置，不能这里一份、那里一份还各不相同
- **数据库连接池**：连接很贵，必须复用，不能每次请求都 `new` 一个
- **日志器**：所有模块往同一个日志里写

如果放任大家随便 `new`，就会出现：配置不一致、连接耗尽、日志写到一堆不同的地方。单例模式就是**从机制上杜绝这种「多实例」的可能**。

## 应用场景（Go 后端）

- 全局配置（读一次，到处用）
- 数据库 / Redis 连接池
- 日志、监控、埋点等全局组件
- 需要「惰性初始化 + 只初始化一次」的资源

## 优势 ✅

1. **保证唯一**：从根上防止出现多个实例导致的状态不一致
2. **节省资源**：昂贵的资源（连接、大对象）只创建一次，之后复用
3. **全局访问方便**：任何地方拿到的是同一个对象，天然共享状态
4. **线程安全可控**：配合 Go 的 `sync.Once`，能既安全又优雅地做到「只初始化一次」

## Go 的独特姿势：`sync.Once`

这是 Go 给单例模式开的后门（划掉，是「官方外挂」）：

```go
var (
    instance *Config
    once     sync.Once   // 保证 Do 里的代码全局只执行一次
)

func GetConfig() *Config {
    once.Do(func() {       // 只有第一次调用时，这里面的代码才会跑
        instance = &Config{...}
    })
    return instance
}
```

`sync.Once.Do` 内部做了加锁和原子标记，**即使有成百上千个 goroutine 同时第一次调用**，也保证初始化代码只执行一次。比自己手写 `if instance == nil { lock... }`（双重检查锁）要安全、简洁得多。

## 何时用 / 何时不用

**用**：对象真的需要全局唯一，且创建成本高或必须共享状态。

**别用**：
- 对象没有「唯一」需求，只是想「方便拿到」——这更适合用依赖注入，而不是单例
- 单例会让代码变得**难以测试**（全局状态容易被污染、测试之间互相影响），所以别滥用

## 一句话总结

> 需要一个「全局唯一」的东西时，用它；Go 里就认准 `sync.Once`，别自己造轮子。
